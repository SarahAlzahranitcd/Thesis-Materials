Refined Metadata Annotation v0.2 — Work in progress

Refined version (MMV v0.2). This workflow allows lifecycle metadata to be created for any mapping type without requiring a mapping file to be uploaded first. Output uses the MMV v0.2 ontology. Required fields are marked with *. Hover the ? icons for guidance on each field.

Mapping Project

?A short identifier used to mint IRIs for this mapping project (no spaces). Example: era_uplift_2026.
?A human-readable title for the mapping project.
?The category of mapping being documented. Reuses mqv:hasMappingType.

Stakeholder

?Given name of the stakeholder. Mapped to foaf:givenName.
?Family name of the stakeholder. Mapped to foaf:familyName.
?The stakeholder's role in the project. Mapped to mmv:hasRole.
?Relevant expertise or experience. Mapped to mmv:hasBackground.
?The organisation the stakeholder belongs to. New in v0.2: mapped to foaf:organization.
?URL of the stakeholder's professional or personal homepage. New in v0.2: mapped to foaf:homepage.

Analysis Phase

?The intended purpose or goal of the mapping project. Mapped to mmv:hasPurpose.
Example purposes:
  • Transform CSV electoral division data into RDF for publication as Linked Data.
  • Align the FIBO and SCOR ontologies to support cross-domain financial supply-chain queries.
  • Interlink OSi Irish Places with Wikidata entities for a heritage knowledge graph.
?The subject area of the mapping (e.g., medical, geospatial, cultural heritage). Mapped to mmv:hasMappingDomain.
?A specific requirement the mapping must meet. Mapped to mmv:hasRequirement.
?An assumption about the source data, target model, or transformation logic. Mapped to mmv:hasAssumption.
?An assumption about domain semantics that affects mapping interpretation. Mapped to mmv:hasDomainAssumption.
?A technical constraint that influences implementation. Mapped to mmv:hasTechnicalRequirement.
?A known risk or issue. Mapped to mmv:hasRiskOrIssue.

Input Dataset (linked from Analysis)

?Human-readable name of the input file or dataset. Mapped to mmv:hasInputName.
?Concise description of the input content. Mapped to mmv:hasInputDescription.
?Where the input dataset is hosted or originates. Mapped to mmv:hasInputSource.
?Who created the input dataset. Mapped to mmv:hasInputCreator.
?Type of input data. Mapped to mmv:hasInputType.
?File format or media type. Mapped to mmv:hasInputFormat.

Design Phase

?A modelling or reuse decision taken during design. Mapped to mmv:hasDesignDecision.
?The rationale for the design decision. Mapped to mmv:hasJustification.
?A quality metric to be applied during testing. The label is recorded; the metric is linked via mmv:hasPlannedQualityMetric to a dqv:Metric instance.

Development Phase

?When development began. Mapped to prov:startedAtTime.
?When development concluded. Mapped to prov:endedAtTime.
?Software tools or platforms used. Mapped to mmv:hasTool.
?How the mapping was produced. Reuses mqv:hasMappingMethod. Choose the option that best reflects the level of human involvement.
?Concrete syntax of the mapping. Reuses mqv:hasMappingFormat.
?Any algorithmic approach used to generate or validate the mapping. Mapped to mmv:hasMappingAlgorithm.

Mapping Artefact

?A persistent identifier for the resulting mapping artefact. Mapped to mmv:hasIdentifier.
?A human-readable title for the mapping artefact. Mapped to dcterms:title.
?A short description of the mapping artefact. Mapped to mmv:hasDescription.
?If this mapping is a revision of an earlier version, the IRI of the previous version. New in v0.2: mapped to prov:wasRevisionOf.

Testing Phase

?Type of testing or validation performed. Mapped to mmv:hasTestingType.
?When the testing activity was performed. Mapped to prov:generatedAtTime.
?Outcome of the testing activity. Mapped to mmv:hasTestingResult.
?A link to a SHACL validation report or equivalent constraint-checking output. New in v0.2: linked via mmv:hasValidationReport to an mmv:ValidationReport instance.
?A short description of what the validation report covers.

Maintenance Phase

?Person or organisation responsible for publishing the mapping artefact. Mapped to mmv:hasPublisherName.
?Where the published mapping artefact is hosted. Mapped to mmv:hasPublisherSource.
?Version identifier for the mapping artefact. Mapped to mmv:version.
?When this version of the mapping artefact was created or released. Mapped to mmv:hasVersionDateTime.

Choose output format

Both formats encode the same MMV v0.2 metadata. Choose the representation that fits your downstream tooling.
